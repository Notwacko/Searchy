# Searchy — contributor brief

Searchy is a native macOS browser (Swift 6, SwiftUI + AppKit, WebKit). Goals: tiny memory, instant launch, great UI.
Target macOS 26+ (this Mac runs macOS 27, Xcode 27, Swift 6.4). Project is generated by `xcodegen` from `project.yml`.

## Layout
```
Sources/App        SearchyApp (scenes), AppDelegate, Commands (menu bar), DebugBridge (dev-only remote control)
Sources/Model      Tab, BrowserModel (one per window), Space, Session, Route (per-tab network routes)
Sources/Web        WebEngine (configs/data stores/scripts), TabCoordinator (WK delegates + page messages), ContentBlocker, DownloadManager
Sources/UI         SwiftUI views (RootView, Sidebar, Bars, CommandBar, ContentArea, Sheets, SettingsView, MemorySheet…)
Sources/Support    Paths, Preferences, stores (History=SQLite, Bookmarks, Favicons, HiddenElements, SiteSettings), MemoryManager
Sources/Proxy      Traffic Lab engine: TrafficProxy (MITM), CertificateAuthority, HTTPMessage, FlowStore (TrafficLab state)
Sources/Agent      AutomationTypes.swift = the shared AI contract (JSONValue, ToolSpec, ToolResult, AgentBrain, AgentEvent)
Sources/Extensions ExtensionManager (WKWebExtension; currently a stub)
Resources/Scripts  bridge.js (every page), picker.js, reader.js (injected on demand into the isolated "Searchy" content world)
```

## Conventions (the compiler will enforce most of these)
- Swift 6 language mode with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`: everything is `@MainActor` unless marked `nonisolated`.
  Plain data types and anything touched from network/background queues must be `nonisolated` (and `Sendable`).
- No `NSLock.lock()/unlock()` inside `async` functions — use `OSAllocatedUnfairLock.withLock`. `SecIdentity`/`NSEvent`/`Any` are not Sendable.
- A `Set` literal with duplicate elements crashes at runtime; build sets from arrays.
- WebKit delegate methods in Swift: the **async** form can have a *different* Swift name than you expect
  (e.g. auth challenge is `webView(_:respondTo:)`, media capture is `webView(_:decideMediaCapturePermissionsFor:initiatedBy:type:)`).
  Check `WK_SWIFT_ASYNC_NAME` in `$(xcrun --show-sdk-path)/System/Library/Frameworks/WebKit.framework/Headers/*.h`. A wrong name compiles
  but is silently never called. The debug command `delegateCheck` verifies the selectors at runtime.
- `Info.plist` has `NSAppTransportSecurity: NSAllowsArbitraryLoads` (a browser must load http://). Do not add the other ATS keys (they disable it).
- Prefer system components and semantic styles; Liquid Glass (`.glassEffect`) only on floating chrome, never stacked.
- Keep memory tiny: no eager work at launch, lazy web views (a blank tab has none), release things when tabs sleep.
- Never block the main thread with I/O or sqlite; use background queues/actors.

## Building and running WITHOUT disturbing anyone
Other people (and the user) may have Searchy running. **Never `pkill -x Searchy` / `killall Searchy`.** Track your own PID.
1. Work only inside your own workspace copy (see below). Never edit `/Users/wacko/Documents/Searchy` until delivery.
2. The repo lives under iCloud-synced ~/Documents, which breaks codesigning of build products — always build with a
   `-derivedDataPath` outside it (your workspace is under ~/Library/Caches, which is fine).
3. Build:  `cd <workspace>/repo && xcodegen generate && xcodebuild -project Searchy.xcodeproj -scheme Searchy -configuration Bench -derivedDataPath ../dd build 2>&1 | grep -E "error:|BUILD"`
   (`Bench` = optimized + the debug bridge; `Debug` also has the bridge.)
4. Run an isolated instance (own data folder, own debug channel, no clash with the user's app):
   `PID=$(scripts/launch-isolated <workspace>/dd/Build/Products/Bench/Searchy.app <workspace>/home)`; later `kill $PID`.
   Drive it with `SEARCHY_HOME=<workspace>/home scripts/dbg '{"cmd":"state"}'` (see Sources/App/DebugBridge.swift for commands; add your own
   commands there for testing — they are compiled out of Release).
5. There is **no Screen Recording permission**, so `screencapture` fails. `scripts/dbg '{"cmd":"snapshot","path":"…png"}'` renders the window
   itself (SwiftUI chrome + page composite) — it can't draw Liquid Glass/materials, so use it for layout only. Read PNGs with the Read tool.
6. Privacy: never print or log passwords, cookies, tokens or personal browsing data from real browser profiles on this Mac. Counts only.

## Delivering
Put everything in your workspace first, then deliver:
- New files go into the main tree under **your owned directory** (given in your task) — copy them there at the end.
- Edits to files you don't own (Tab.swift, BrowserModel.swift, WebEngine.swift, Commands.swift, project.yml, …): do NOT apply them to the main tree.
  Produce `<workspace>/integration.patch` (`diff -ruN <workspace>/base/<path> <workspace>/repo/<path>` for just the files you changed) and describe it.
- Write `<workspace>/DELIVERY.md`: what you built, what's verified (with the evidence), what's not, exact steps to integrate, any new Info.plist /
  entitlement / project.yml needs, and known risks. Be honest about anything unverified.
- Tests: add XCTest files under `Tests/` for pure logic (they run with `xcodebuild test`); keep them hermetic (use SEARCHY_HOME / temp dirs).
